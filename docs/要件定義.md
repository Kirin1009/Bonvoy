# Bonvoyラリー 要件定義書

- 作成日: 2026-08-10
- 対象バージョン: v0.1.0（ベース版）以降
- ステータス: ドラフト（未決事項は §9 に集約）

---

## 1. 目的・コンセプト

マリオット ボンヴォイ系列のホテルを泊まり歩き、泊まった宿に判子を押して集める**個人用スタンプ帳**。

- 「ラリー（お題）」と「判子帳（コレクション一覧）」の二層構造
- 判子はホテルごとに自動生成し、**泊まるまで伏せる**（開けてからのお楽しみ）
- 姉妹アプリ Sauna470s / サ道場 東海 の判子エンジンを移植した独立プロジェクト。データ・コードの共有はしない

### やらないこと（非目標）

- 予約・ポイント残高などBonvoy公式機能との連携（API連携はしない）
- 複数端末間の自動同期・アカウント機能（記録は端末ローカル。共有はバックアップの手動受け渡しで足りる）
- 不特定多数への公開を想定した機能（利用者は2名で固定）

## 2. ユーザーと利用シーン

| 項目 | 内容 |
|---|---|
| ユーザー | Shun（岐阜在住）と妻・紗也乃の2名のみ |
| 端末 | 各自のスマートフォン（幅390pxを基準に確認） |
| 主な利用シーン | ①チェックイン時にホテルの敷地内でGPS判子を押す ②旅の計画時に「☆泊まりたい」を眺める ③帰宅後に判子帳を眺めてニヤニヤする |

記録は端末ごとに独立でよい（夫婦で判子帳が別冊になるのはむしろ味）。

## 3. スコープ（収録範囲）

**方針: 日本国内のBonvoy参画ホテル全店を最終目標とし、段階的に収録する。**

| 段階 | 範囲 | 備考 |
|---|---|---|
| 第1弾 | 東海4県（岐阜・愛知・三重・静岡）＋よく行く都市圏（京阪神・首都圏） | 生活圏から。ここで `EDITION` に収録日を付けて運用開始 |
| 第2弾 | 残りの国内全店 | 全店制覇ラリーが実質を持つのはここから |
| 対象外 | 海外店舗 | 泊まったら個別に追加する運用も可（未決事項 §9-1） |

### データ投入の絶対条件（実データ主義）

- 名称・都市・座標は**実在のもののみ**。捏造データは絶対に入れない
- 座標はGoogleマップ等で**1軒ずつ目視確認**する。ジオコーディング一括変換は不可（サウナ側で精度75m〜2.1kmのばらつきを実測済み。座標が違うとGPSチェックインが壊れる）
- 全店投入が済んだ収録単位ごとに `EDITION` を収録日で更新する

## 4. 機能要件

### 4.1 実装済み（v0.1.0 ベース版）

| # | 機能 | 内容 |
|---|---|---|
| F-01 | 判子帳 | 区分（ラグジュアリー/プレミアム/セレクト/長期滞在）ごとに全収録ホテルの判子をグリッド表示。未泊は形と「？」のみの伏せ判子 |
| F-02 | ホテル判子の自動生成 | `hotelSeal()`。形=区分（六角=luxury/丸=premium/角=select/五角=longstay）、中央=施設名頭文字、肩=都市名。かすれ・傾きつき。画像アセット不要 |
| F-03 | ラリー（お題） | `QUESTS` 4本（はじめての一泊/ラグジュアリー巡り/ブランド集め/全店制覇）。対象はHOTELSから動的に組む。達成で「満願」表示 |
| F-04 | GPSチェックイン | 現在地から半径内（200〜2000m、既定800m）の収録ホテルを検索して判子。複数該当時は選択シート |
| F-05 | 手動判子 | ホテルカードから「泊まった」で押す。取り消しも可（confirm付き） |
| F-06 | ☆泊まりたい | ホテルカードからトグル。一覧に★表示 |
| F-07 | ホテルカード | 判子・宿泊日・ブランド/区分バッジ・手動判子・☆・Googleマップ起動を集約 |
| F-08 | 判子演出 | 押印時のスタンプアニメーション＋施設名・日付表示 |
| F-09 | PWA/オフライン | manifest.json + sw.js。ホーム画面追加・オフライン起動 |

### 4.2 追加予定（優先度順）

| # | 機能 | 内容 | 優先度 |
|---|---|---|---|
| F-10 | ホテルデータ投入 | §3の第1弾範囲を実データで投入し `EDITION` 付与 | ★★★ 最優先 |
| F-11 | アイコン差し替え | 現在サウナハットのキャラを流用中。Bonvoy用（ホテル/判子モチーフ）に描き替え | ★★ |
| F-12 | ラリー拡充 | 都道府県制覇・カテゴリ制覇（プレミアム巡り等）・ブランド別制覇など。雛形は既存 `QUESTS` の `goal`/`test` 方式を踏襲 | ★★ |
| F-13 | 満願之証 | ラリー全達成時の証書表示（サ道場の型を流用可） | ★ |
| F-14 | 記録項目の拡充 | 泊数（同一ホテル複数回）・メモ・採点など。**データ形式変更を伴うためMAJOR判断が必要**（§9-2） | ★ 要検討 |
| F-15 | バックアップ | 記録のエクスポート/インポート（JSON手動受け渡し）。機種変更・夫婦間共有に使う | ★★ |

## 5. データ要件

### 5.1 ホテルマスタ（コード内定数 `HOTELS`）

```
1行 = {id, name, city, pref, lat, lng, brand, cat}
```

- `id`: 一意の短いスラッグ（例: `ritz-nagoya`）。**一度公開したら変更しない**（stays/wantsのキーになるため）
- `brand`: `BRANDS` のキー（19ブランド定義済み）
- `cat`: Bonvoy公式区分 `luxury` / `premium` / `select` / `longstay`
- 廃業・リブランド時は削除せず、brand変更または表示上の扱いを検討（判子の履歴を消さない）

### 5.2 ユーザー記録（localStorage `bonvoy:v1`）

```
{stays: {hid: "YYYY-MM-DD"}, wants: {hid: "YYYY-MM-DD"}, radius: 800}
```

- キー名 `bonvoy:v1` と形式は**互換を壊さない**。拡張は追加キーで行い、既存キーの型変更はMAJORバージョンアップ＋移行処理が必須
- 保存失敗時は通知（実装済み）

## 6. 非機能要件

| # | 要件 |
|---|---|
| N-01 | **1ファイル主義**: index.html単体完結。外部ライブラリ・外部フォント・ビルド工程を導入しない |
| N-02 | オフライン動作: SWキャッシュで機内モードでも判子帳が開ける（GPSチェックインは除く） |
| N-03 | 表示確認はスマホ幅390pxで行う（Playwright chromium, `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`） |
| N-04 | データ量: 国内全店（100軒規模）でもコード内定数で成立するサイズに収める |
| N-05 | 世界観: クリーム地・こげ茶・判子朱（Sauna470s系）＋紺 `--navy #3A4A6B` のホテル調アクセントを維持 |

## 7. バージョニング・リリース

- バージョンは `APP_VERSION` の1箇所のみ（現在 `0.1.0`）。SW登録・キャッシュ名は自動追従、sw.jsは手で触らない
- MAJOR = データ互換の変更 / MINOR = 機能追加 / PATCH = 修正
- `EDITION` = ホテルデータの収録日（現在「準備中」）。データ更新のたびに付け替える
- 配布: GitHub Pages（mainブランチ直デプロイ） https://kirin1009.github.io/bonvoy/

## 8. ロードマップ

1. **v0.2.0** — 第1弾ホテルデータ投入＋`EDITION`付与（F-10）、バックアップ（F-15）
2. **v0.3.0** — アイコン差し替え（F-11）、ラリー拡充（F-12）
3. **v0.4.0** — 満願之証（F-13）
4. **v1.0.0 または v0.5.0** — 記録項目の拡充（F-14。データ形式を変えるならMAJOR）

## 9. 未決事項（オーナー判断待ち）

1. **収録範囲の最終確定** — §3の「第1弾=東海＋京阪神・首都圏」案でよいか。海外で泊まった店を個別追加する運用を認めるか
2. **記録項目の拡充方針（F-14）** — 泊数を数えたいか？ 数えるなら `stays` の値を日付文字列→オブジェクトに変える必要があり、`bonvoy:v2` への移行（MAJOR）になる。当面は「初回宿泊日のみ」で運用し、欲しくなってから判断でもよい
3. **採点項目** — サ道場の採点画面の型を流用する場合、ホテルで何を採点するか（朝食・ラウンジ・風呂・眺望など）
4. **エリート泊数系ラリー** — Bonvoyエリート資格の泊数（例: 年50泊）をお題にするか。年単位のリセットが絡むため要設計
