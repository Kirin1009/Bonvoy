# Bonvoyラリー 要件定義書

- 作成日: 2026-08-10（同日、オーナー決定を反映して改訂）
- 対象バージョン: v0.1.0（ベース版）以降
- ステータス: 確定（残る未決事項は §9）

---

## 1. 目的・コンセプト

マリオット ボンヴォイ系列のホテルを泊まり歩き、泊まった宿に判子を押して集める**個人用スタンプ帳**。

- 「ラリー（お題）」と「判子帳（コレクション一覧）」の二層構造
- 判子はホテルごとに自動生成し、**泊まるまで伏せる**（開けてからのお楽しみ）
- 姉妹アプリ Sauna470s / サ道場 東海 の判子エンジンを移植した独立プロジェクト。データ・コードの共有はしない

### やらないこと（非目標）

- 予約・ポイント残高などBonvoy公式機能とのAPI連携（公式APIは個人に提供されていない。履歴取り込みは §4.3 F-16 の方式で検討）
- 複数端末間の自動同期・アカウント機能（記録は端末ローカル。共有はバックアップの手動受け渡しで足りる）
- 不特定多数への公開を想定した機能（利用者は2名で固定）

## 2. ユーザーと利用シーン

| 項目 | 内容 |
|---|---|
| ユーザー | Shun（岐阜在住）と妻・紗也乃の2名のみ |
| 端末 | 各自のスマートフォン（幅390pxを基準に確認） |
| 主な利用シーン | ①チェックイン時にホテルの敷地内でGPS判子を押す ②旅の計画時に「☆泊まりたい」を眺める ③帰宅後に判子帳を眺めてニヤニヤする |

記録は端末ごとに独立でよい（夫婦で判子帳が別冊になるのはむしろ味）。

## 3. スコープ（収録範囲）【決定】

**対象: アジアのBonvoy参画ホテル。ただしフェアフィールド等の廉価・長期滞在系ブランドは収録しない。**

### 3.1 対象ブランド

- **除外**: フェアフィールド、レジデンス・イン、および同系統の長期滞在・廉価ブランド（エレメント、タウンプレイス・スイーツ、アパートメンツ by ボンヴォイ、マリオット・エグゼクティブ・アパートメント、フォーポイント・フレックス等）
  - 除外ブランドのホテルは `HOTELS` に投入しない（判子帳・ラリーの母数に入らない）
  - 結果として `cat:"longstay"` はほぼ空になる見込みだが、区分定義と五角判子は将来のために残す
- **収録**: 上記以外のluxury / premium / selectブランド
- アジアには現行 `BRANDS`（19件）にないブランドが存在する（ブルガリ、トリビュート・ポートフォリオ、デザインホテルズ等）。**データ投入時に実在を確認しながら `BRANDS` に追記する**（実データ主義はブランド定義にも適用）

### 3.2 段階的収録

アジア全域は数百軒規模になるため、座標1軒ずつ確認の原則を守れる単位で刻む。

| 段階 | 範囲 | 備考 |
|---|---|---|
| 第1弾 | 日本国内の対象ブランド全店 | ここで `EDITION` を付けて運用開始 |
| 第2弾 | 泊まる予定・泊まったことのある国から順次（韓国・台湾・タイ・シンガポール等） | 旅行が決まった国を先に整備する運用 |
| 第3弾 | アジアの残り | 全店制覇ラリーの最終形 |
| 対象外 | アジア以外（欧米・中東・オセアニア等） | 泊まった場合の扱いは §9-1 |

### 3.3 データ投入の絶対条件（実データ主義）

- 名称・都市・座標は**実在のもののみ**。捏造データは絶対に入れない
- 座標はGoogleマップ等で**1軒ずつ目視確認**する。ジオコーディング一括変換は不可（サウナ側で精度75m〜2.1kmのばらつきを実測済み。座標が違うとGPSチェックインが壊れる）
- 収録単位ごとに `EDITION` を収録日で更新する
- 海外ホテルの `pref`/`city` は「国・都市」に読み替えて使う（例: `pref:"タイ"`, `city:"バンコク"`）

### 4.3 検討中（実験枠）

| # | 機能 | 内容 |
|---|---|---|
| F-16 | Marriott履歴取り込み | 公式APIは個人向けに存在しないため、**Bonvoyサイト/アプリのアクティビティ履歴を画面からコピーして貼り付け→テキストをパースして一括判子**する方式を検討。1ファイル主義の範囲内で実装可能。課題は ①ホテル名の表記ゆれと `HOTELS` のマッチング（英語名↔日本語名の対応表が必要） ②履歴画面のフォーマット変更に弱い。まず自分の履歴1年分でパース実験してから判断する |

### 4.4 採点項目（F-17 提案）

ホテル1軒につき5項目を5段階（サ道場の採点画面の型に合わせる）＋ひとことメモ。

| 項目 | 見るところ |
|---|---|
| 部屋 | 広さ・眺望・アップグレードの引き |
| 朝食 | 内容・会場の気持ちよさ |
| ラウンジ | 有無・カクテルタイム・混み具合（ない場合は未採点でスキップ可） |
| 風呂 | 大浴場・スパ・プール・バスタブの質 |
| もてなし | 接客・エリート待遇・レイトチェックアウトの通り具合 |

- 総合点は5項目の平均を自動表示（手入力しない）
- 採点は**ホテル単位**（宿泊単位ではない）。再訪したら上書き更新でよい
- 項目名はUI上4文字以内に収める（390px幅で崩れないため）

### 4.5 エリート泊数ラリー（F-12 内、決定: やる）

- Bonvoyエリート資格の必要泊数をお題化する: **シルバー10泊 / ゴールド25泊 / プラチナ50泊 / チタン75泊 / アンバサダー100泊**
- 集計は**暦年（1/1〜12/31）リセット**。泊数記録（F-14）の チェックイン日＋泊数 から当年分を合算する
- 表示は「今年の泊数」ゲージ＋到達済みティアの判子。年が変わると自動でゲージが戻る（過去年の達成履歴は記録から再計算できるので保持不要）
- ティア泊数はBonvoy公式改定があれば追従する（数値はコード内定数1箇所にまとめる）

## 5. データ要件

### 5.1 ホテルマスタ（コード内定数 `HOTELS`）

```
1行 = {id, name, city, pref, lat, lng, brand, cat}
```

- `id`: 一意の短いスラッグ（例: `ritz-nagoya`、海外は `jw-bangkok` のように都市の英語名）。**一度公開したら変更しない**（記録のキーになるため）
- `brand`: `BRANDS` のキー。アジア展開で不足するブランドは実在確認のうえ追記
- `cat`: Bonvoy公式区分 `luxury` / `premium` / `select`（`longstay` は除外方針により原則使わないが定義は残す）
- 廃業・リブランド時は削除せず、brand変更または表示上の扱いを検討（判子の履歴を消さない）

### 5.2 ユーザー記録・現行（localStorage `bonvoy:v1`）

```
{stays: {hid: "YYYY-MM-DD"}, wants: {hid: "YYYY-MM-DD"}, radius: 800}
```

### 5.3 ユーザー記録・次期（`bonvoy:v2`、F-14/F-17で移行）

```
{
  stays: {hid: [{d:"YYYY-MM-DD", n:1}, ...]},   // 宿泊ごとに チェックイン日d＋泊数n。配列順=古い順
  scores: {hid: {room:4, bf:5, lounge:3, bath:4, svc:5, memo:"..."}},  // 採点はホテル単位
  wants: {hid: "YYYY-MM-DD"},
  radius: 800
}
```

- **移行**: v1の `stays[hid]="date"` → v2の `stays[hid]=[{d:"date", n:1}]`。初回起動時に自動変換し、変換前のv1データは `bonvoy:v1:backup` に退避してから書き換える
- GPS/手動判子は「宿泊レコードを1件追加」に意味が変わる（同じ日の二重押しは弾く）
- 泊数nの既定は1。ホテルカードから後追いで編集できるようにする
- 判子済み判定は `stays[hid].length > 0`。既存の判子帳・ラリーはこの読み替えだけで動く
- この移行はMAJOR相当（`APP_VERSION` 1.0.0）

## 6. 非機能要件

| # | 要件 |
|---|---|
| N-01 | **1ファイル主義**: index.html単体完結。外部ライブラリ・外部フォント・ビルド工程を導入しない |
| N-02 | オフライン動作: SWキャッシュで機内モードでも判子帳が開ける（GPSチェックインは除く） |
| N-03 | 表示確認はスマホ幅390pxで行う（Playwright chromium, `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`） |
| N-04 | データ量: アジア対象ブランド全店（数百軒規模）でもコード内定数で成立させる。1軒約120バイト×500軒≒60KBで許容範囲。判子帳グリッドの描画が重くなったら国・地域での絞り込み表示を入れる |
| N-05 | 世界観: クリーム地・こげ茶・判子朱（Sauna470s系）＋紺 `--navy #3A4A6B` のホテル調アクセントを維持 |

## 7. バージョニング・リリース

- バージョンは `APP_VERSION` の1箇所のみ（現在 `0.1.0`）。SW登録・キャッシュ名は自動追従、sw.jsは手で触らない
- MAJOR = データ互換の変更 / MINOR = 機能追加 / PATCH = 修正
- `EDITION` = ホテルデータの収録日（現在「準備中」）。データ更新のたびに付け替える
- 配布: GitHub Pages（mainブランチ直デプロイ） https://kirin1009.github.io/bonvoy/

## 9. 未決事項

1. **アジア以外で泊まった場合の扱い** — 対象外のままか、泊まった店だけ個別収録を認めるか（個別収録なら「全店制覇」の母数に入る点に注意）
